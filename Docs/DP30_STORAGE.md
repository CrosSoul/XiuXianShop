# DP-30 储存物品基础闭环

2026-09-10；基线 `076fa29`（DP-25）。[DP-30](https://zzrzzrzzr11.atlassian.net/browse/DP-30) / [G-01](https://zzrzzrzzr11.atlassian.net/wiki/spaces/D/pages/1736718) / [数据规范](https://zzrzzrzzr11.atlassian.net/wiki/spaces/D/pages/688131)。交付待用户验收，不启动DP-31。

## 当前实现

- 仓库仍是根层区域。新增类别追加到旧枚举末尾，保留既有数值。StorageContainer / EquipmentContainer / PortableContainer 与旧 Container、ProductionEquipment 分开。
- 物品定义的 storageSize 独立于外部 cells；设备匣按 compatibleEquipmentIds 接纳生产设备。未配置内部尺寸不能打开；未配置兼容设备不会自动接纳全部设备。
- 内部物品仍在同一 ShopSession.Items 列表，StorageItemId 指向容器实例。复用 Fits / CanMove / Move、现有形状和R/F变换；没有独立库存副本。关闭、移动和重开不复制或移除内容，存读档保留稳定实例ID、所属容器、位置、方向和购买历史。
- 点击仓库中的储存物品打开独立窗口，拖动标题可移动窗口，右上角×关闭。当前一次打开一个窗口，切换窗口保留旧内容。普通物品可从仓库拖入、拖回，也沿用自有物品其他区域的合法搬运规则。
- 储存物品只能留在仓库，禁止互相嵌套；当前不支持储存物品交易或丢弃。生产设备仅仓库或兼容设备匣；普通/便携储存拒绝生产设备。未付款顾客货物不能收入储存物品。
- 满格/碰撞/越界/类别失败不转移物品，给出明确原因。闭合容器内物品不被“一键摆入”偷偷取走；现有即时加工也只访问根层原料。

## 数据边界与进入方式

当前Confluence物品目录v21：jade仍是StorageContainer/外部3×3草稿，内部尺寸未定；基础储物匣、设备匣、生产设备记录也仍为草稿。Unity旧jade（Container、2×2、基础价值14）和所有现有资产保持不变，没有导入草稿或新建同名正式商品。

可玩验证入口：打开ShopPrototype场景并Play，菜单 **XiuXianShop > Validation > Start DP30 Storage Example (resets Play session)**。它重置当前Play会话，生成明确隔离的test-*定义，不保存为正式资产：

| 样例 | 外部 / 内部 | 用途 |
| --- | --- | --- |
| 储物匣 | 3×3 / 10×10 | 已确认空间规格的可玩闭环 |
| 设备匣 | 3×3 / 6×6 | 内部6×6暂定，只验证兼容分类 |
| 测试生产设备 | 2×2 | 隔离占位，不是正式炼丹炉或设备商品 |
| 便携储存 | 2×3 / 3×3 | 验证分类与禁止嵌套，不实现外出 |

这些样例不参与供货/出售，未设正式价格、解锁或获取方式。正常开局仍为原7件商品，需上述菜单体验储存，不能点击旧jade获得未经确认的10×10容量。

## 存档

新增储存状态使用版本3，默认路径 `UserSettings/ShopStoragePreparation-v3.json`。DP30菜单使用 `Temp/DP30VerificationSave.json`，通过同一实际日历保存/读取方法验证。

旧月度 `ShopMonthlyPreparation-v2.json` 及旧日制文件不读写、不删除、不覆盖；显式尝试加载版本2或1也明确拒绝，当前会话保留。没有自动转换老存档或兼容框架。新定义字段改变目录签名，沿用既有签名验证而不新增哈希；需要旧进度转换时须另定并实现迁移，不声称v2已兼容。

## 手动复验（约3分钟）

1. 从上述菜单开隔离样例，点击储物匣，拖入凝气草与木剑；按R/F验证形状、越界红色提示及合法放置。
2. 拖标题移动窗口，关闭；在仓库移动整个匣子，再点击打开，两件内容仍在。分别拖回空格，确认原物品与方向保留。
3. 拖生产设备进储物匣应拒绝，进设备匣应成功；把草药拖进设备匣、把另一匣子拖入匣内均拒绝。
4. 营业准备阶段通过日历保存/读取，重新打开匣子检查内容。此菜单存档为临时文件，不用它保留正常游玩进度。
