## 执行要求

先读取 AGENTS.md、最新提交、工作区、现有物品实例／格子／存档实现及已批准数据。用户已验收上一轮DP-25，不重复迁移月度时间。优先复用现有拖拽、形状、旋转／翻转及物品身份机制。

1. 仓库是根层区域，不是物品。StorageContainer、EquipmentContainer、PortableContainer为不同类别；空间储存与灵气资源容器不是同一能力。储存物品具有独立外部形状及内部宽高，平时只能放在仓库；点击打开可拖动的独立储存弹窗。
2. 使用已确认的基础储物匣规格：外部3×3、内部10×10。内部沿用现有有限格子和合法摆放规则。实现普通物品放入、取出、关闭重开、移动容器后重开；同一容器和内容保持原实例，不复制、不清空，不改写历史购买价值。
3. 复用储存机制支持设备储存：只接纳兼容生产设备；普通物品储存和便携储存不接纳生产设备；储存物品禁止互相嵌套。基础设备匣内部6×6仍为暂定值，仅作明确标记的隔离测试配置。没有已批准设备数据时，用隔离测试定义验证分类，不自动导入草稿或制造正式商品。
4. 核对现有Container、jade等资产与正式类别的差异，不将jade草稿3×3直接覆盖旧资产，不因改名创建重复物品。未确认的容量、价格、稳定ID和设备兼容表保持未定，仅做有依据的最小适配。
5. 装有内容容器的交易／丢弃、满仓返回、窗口并行等尚未全部定案，不自行发明长期规则；不支持的操作应明确限制，不能默默丢失或复制内容。若已有存档能力，验证本轮新增状态在实际保存／读取路径中恢复；破坏性迁移先报告并等待授权。

## 验收与交付

实际试玩完成：仓库放置储物匣 → 打开 → 放入两件不同形状物品 → 关闭并移动 → 重开 → 取回原物品。验证内部占位、旋转／翻转、空间不足不转移、禁止嵌套、普通储存拒绝生产设备、设备储存分类限制、实例及历史购买价值连续。涉及已有存档时验证保存／读取。保留营业、双向交易、DP-23让价及DP-25月度推进的相关回归。

运行真实相关Edit/Play测试，报告执行数、通过、失败、跳过及实际证据。提供修改文件、提交信息、可复现试玩步骤与仍待设计的边界。完成后提交供用户验收，不自动将Jira标记Done。

## 范围与最小必要防御

不实现炼丹、生产设备运行、外出、战斗、实体灵石或全面UI重构。先理解并复用现有代码，只在真实放置、所有权、内容转移和存档边界保留必要校验；不增加未来系统框架、重复兜底、无需求哈希／校验和或大量重复测试。明确目标后直接推进，只有关键未定规则或必须授权的破坏性操作才暂停。
