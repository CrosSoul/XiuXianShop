# 第一阶段原型：试玩指南

## 入口

打开 `Assets/Scenes/ShopPrototype.unity`，点击 Unity Play。也可以使用菜单 `XiuXianShop > Open Playable Prototype`。场景和 ShopCatalog 引用已经配置，不需要手动创建对象。

建议最大化 Game 窗口，方便阅读中文和格子。界面会等比缩放以显示完整布局。退出 Play 再进入会重开第 1 天；当前没有磁盘存档，睡觉跨日会保留本次 Play 会话中的资源。

## 操作

| 操作 | 方法 |
| --- | --- |
| 移动 | 鼠标左键拖动物品的有色占格，放入目标容器 |
| 查看物品 | 点击物品，在背包下方查看名称、归属和价格 |
| 旋转 | 拖动时按 R，或选中后点击“旋转” |
| 水平翻转 | 拖动时按 F，或选中后点击“水平翻转” |
| 取消拖动 | Esc；放在格子外或非法位置也会保留原位 |
| 放置预览 | 绿色可以放；红色表示碰撞、越界或容器规则不允许 |
| 买入 | 顾客商品在柜台，点击“确认收购”；收进背包后扣款 |
| 卖出 | 将当前顾客指定的展示商品拖到柜台，或点击摆放按钮，再确认出售 |
| 炼丹 | 背包中有 1 凝气草和 1 灵露，点击“炼制回气丹” |
| 跨日 | 结束营业后点击“睡觉 / 下一天” |

背包 10×7，展示柜 6×4，柜台 5×4。三个容器都使用同一套实际占格规则。物品上的“己”表示玩家所有，“客”和蓝色边框表示顾客所有。顾客商品不能未经结算拖进背包。

## 第一次两天试玩（约 5–10 分钟）

初始有 120 灵石、7 件物品和已拥有的丹炉。格子坐标按左上角第 1 列、第 1 行开始计数。

1. 将紫色收购牌放在展示柜左上角；将金色回气丹放在展示柜第 3 列、第 1 行。它们不会重叠。
2. 点击“开始营业”。前四位为供货顾客，依次提供凝气草、灵露、凝气草、灵露。
3. 依次确认四次收购，每次成交后点击“下一位顾客”。花费 14 灵石，余额为 106。
4. 第五位顾客要买展示中的回气丹。把该丹盒拖到柜台左上角，确认出售。余额变为 124，展示柜里的这件丹药真实消失。
5. 点击“结束营业”。点击三次“炼制回气丹”：开局一组原料加上刚买的两组，得到三盒真实占格的丹药。
6. 点击“睡觉”，进入第 2 天。余额 124，收购牌、其他物品、三盒丹药和丹炉保留。
7. 保留左上角收购牌，将三盒丹药分别放在展示柜第 3 列第 1 行、第 5 列第 1 行、第 3 列第 3 行。
8. 开始营业。这次先拒绝四位供货顾客，每次拒绝后点“下一位顾客”，验证不扣灵石。
9. 接着向三位买家逐件摆放并出售丹药。每件收入 18，总余额应为 **178**。
10. 结束营业、睡觉，进入第 3 天。当天队列清空，库存和灵石继续保留，可再次经营。

以上完整路径已经通过真实 Input System 模拟鼠标点击、拖放的 Play Mode 自动测试；仍需开发者亲自试玩来判断操作手感和理解成本。

## 单独体验形状空间

在新一局营业前进行，完成后可重新进入 Play 重置，或把物品移回背包：

1. 将单格灵露放入展示柜左上角。
2. 从凝气草左上方有色格抓起，将其形状的左上角对准同一位置；此时与灵露冲突，预览为红色。
3. 保持拖动，按 F。L 形缺口翻到左上，避开灵露，预览变为绿色，松开可以嵌放。
4. 将四格木剑从顶部格抓起，拖到展示柜最下行的左端。竖放越界；按 R 横放后可以放入。
5. 再尝试把横剑拖到最下行右端越界位置，应回到原位。观察物品总数不变。

## 经营规则

- 收购牌不出售。只要营业前在展示柜里，当天稳定提供两组原料，无随机阻断。
- 展示的每件普通商品吸引一位买家。只展示丹药不会带来原料供货；展示内容不是装饰。
- 营业期间展示锁定。当前买家指定的物品可以从展示柜移上柜台；拒绝或提前闭店会按原位置、原朝向归还。
- 背包可随时整理，炼丹只消耗背包里的玩家原料。展示柜或顾客柜台里的原料不计入。
- 收购钱不足或背包放不下时不扣款。可整理背包，或在柜台旋转顾客物品后再试。
- 回气丹占 2×2；炼丹会考虑原料释放出的空间。如果仍放不下成品，原料不消耗。
- 草收购价 4，灵露 3，丹药售价 18，一组原料的毛利为 11 灵石。
- 每 7 天夜间收房租，首期 20，下期向上取整上涨约 5%。不够支付的部分记为待付房租，后续夜间用现有灵石偿还，不会出现负灵石或强制结束。没有 72 天倒计时。

## 边界与下一步

- 已实现目标书六项主目标的原型及自动验证；实际人工试玩尚未执行。
- 未实现磁盘存档、堆叠、自动整理、多件议价、顾客移动动画、正式美术、音效或任何第二产业。没有战斗、终局或其他范围外系统。
- 当前中文字体从本机 Microsoft YaHei / SimHei 等系统字体加载，已在此 Windows 环境显示验证。跨系统字体和 Player 构建未验证。
- 收尾时 Console 留有一条 Unity Connect 登录令牌交换失败异常，属于编辑器云服务连接，未发现原型脚本异常。若持续出现可检查 Unity 登录和网络；原型不使用该云服务。
- 小 Game 窗口中文字较小，最大化后更易读。自动测试验证操作和状态，不代表所有分辨率和真实鼠标使用习惯都已覆盖。
- 下一步优先亲自跑一遍上述流程，记录拖动锚点、物品识别、文字大小和经营反馈问题；先修复可用性，再增加内容。
