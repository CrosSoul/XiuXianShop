# XiuXianShop 游戏设计

## 日历与行情（DP-17，2026-09-09）

日历显示两周日期、今天与收租日。行情持续 1–3 天，默认每周 2–3 个；不同类型可重叠。相同行情类型生效期间不可重复，结束后隔两个完整游戏日才能重现（第 4 天结束，最早第 7 天再出现）。行情到开始日才公开名称、详情和完整持续条；公开后保留历史，未来尚未开始的行情隐藏。价格仍按当天有效的类别和买卖方向修正。生成缓存与营业准备存档保留已确定安排，不因翻页或读取重抽。详见 [DP-17 交接](DP17_CALENDAR.md)。

## 定位

单人开发的 2D 修仙题材店铺经营游戏 Demo。参考固定视角店铺经营体验，先验证经营循环是否清楚、有反馈、能够重复游玩，再考虑扩展内容。

开发者主要具有策划、关卡设计、UE5 Blueprint 和少量 Paper2D 经验。原型优先采用易理解、易调试的 Unity 实现，不以搭建通用框架为目标。

## 核心体验

1. 营业前配置店铺，为当天经营作准备。
2. 营业中与顾客进行买卖，观察商品和资金变化。
3. 利用产业链将原料加工为商品，为经营提供选择。
4. 结束营业后睡觉推进日期，再开始下一天。

以上是体验方向。加工发生的具体时段、顾客行为、定价与交互细节尚未确定，后续按单次任务逐步明确。

## 第一阶段目标

完成最小可玩闭环：配置 → 营业与交易 → 加工商品 → 结束营业 → 睡觉到下一天 → 再次营业。使用简单占位图形和文字反馈，不制作正式美术。

建议以单个店铺、极少量商品和一条简单加工链验证闭环；具体数量和规则在相关功能任务中确定，不视为已批准的实现规格。

原型验收关注：玩家知道当前阶段、能理解买卖和加工结果、日期能推进、下一天能够继续经营。具体数值与平衡不在项目整理阶段确定。

## 当前状态

- 已完成第一阶段可玩经营原型，入口为 Assets/Scenes/ShopPrototype.unity；原 SampleScene 作为 2D 空场景保留。
- 原型使用三个真实形状格子容器，支持鼠标拖动、旋转、水平翻转、碰撞预览与非法回退。
- 每次开门固定生成五位顾客，各自随机决定买卖方向。空展示柜也来客；可售展示提高买家概率，广告牌提高卖家概率并限定供货类别，营业后展示变化不改变当天客源。
- 展示吸引暂按基础价值计算，仅总基础价值最高的单一类别影响买家偏好和预算；无商品展示时求购类别随机，不要求玩家有货。同类商品价值相加，跨类别不叠加，并列按类别枚举顺序确定。购买历史和谈判修正不作为展示权重。
- 买家持有求购类别和可用预算。柜台支持任意自有物品；整批类别符合且总价不超预算才可出售，成交后买家留场并扣除预算，支持分次或多件购买，随时可切换下一位。
- 玩家物品在三个容器和所有营业阶段均可自由搬动，换客、拒绝、闭店不自动移回未售物品。顾客未付款的供货仍不可拿走。
- 买家资金采用离散档位，当前门槛为 0/30/100/300，基准资金 20/60/150/400，每位在当前档约 ±10% 的整数范围内随机。范围只随跨档变化；档位与概率都可在 ShopCatalog 调整。边界和默认值详见试玩指南。
- 已实现收购、拒绝、炼丹、闭店、睡觉跨日及七日房租。随机来客不保证每日固定材料组数。
- G-05 已接入：基础价值不变；仓库/展示预估等于基础值，柜台预估为交易方向的当前报价。报价按基础值 ×（1 + 有效百分比修正之和），玩家出售默认零售加价 +15%。详情、清单、预算和实际收支使用统一计算；实际买入值记录到实例且不随估值变化，直接获得物品不显示购买值。
- 临时报价边界：逐件四舍五入（中点远离零）后相加，可售品最低 1；同 ID 标签替换，可限定类别和买卖方向。旧固定买卖价仅留作迁移来源。完整边界、当前价格及测试见 [TRADING_SLICE_V3.md](TRADING_SLICE_V3.md)。没有实现市场事件生成与持续系统。
- 界面骨架为左展示、中央顾客/谈判、底部库存、右侧滚动交易清单与物品详情；闭店显示收入、支出、起始和当前余额及变化，睡觉进入下一天。房租沿用原规则，在睡觉时支付。
- 使用颜色格子、静态顾客占位和中文 UI，无正式美术或范围外玩法。详见 FIRST_PLAYABLE_GUIDE.md 和 FIRST_PLAYABLE_VERIFICATION.md。

## 本阶段边界

不默认加入正式美术、大量商品、复杂顾客 AI、战斗、修炼数值、开放世界或联机功能。当前 UI 使用 UGUI 和鼠标拖动；磁盘存档及后续玩法按新任务单独确定，不预建架构。
