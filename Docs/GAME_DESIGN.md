# XiuXianShop 游戏设计

## 定位

单人开发的 2D 修仙题材店铺经营游戏 Demo。参考固定视角店铺经营体验，先验证经营循环是否清楚、有反馈、能够重复游玩，再考虑扩展内容。

开发者主要具有策划、关卡设计、UE5 Blueprint 和少量 Paper2D 经验。原型优先采用易理解、易调试的 Unity 实现，不以搭建通用框架为目标。

## 核心体验

1. 营业前配置店铺，为当天经营作准备。
2. 营业中与顾客进行买卖，观察商品和资金变化。
3. 利用产业链将原料加工为商品，为经营提供选择。
4. 结束营业后睡觉推进日期，再开始下一天。

以上是体验方向。加工发生的具体时段、顾客行为、定价与交互细节尚未确定，后续按单次任务逐步明确。

## 第一阶段目标

完成最小可玩闭环：配置 → 营业与交易 → 加工商品 → 结束营业 → 睡觉到下一天 → 再次营业。使用简单占位图形和文字反馈，不制作正式美术。

建议以单个店铺、极少量商品和一条简单加工链验证闭环；具体数量和规则在相关功能任务中确定，不视为已批准的实现规格。

原型验收关注：玩家知道当前阶段、能理解买卖和加工结果、日期能推进、下一天能够继续经营。具体数值与平衡不在项目整理阶段确定。

## 当前状态

- 仅完成工程检查、开发规则、文档与目录整理。
- 当前场景仍为模板 SampleScene，包含 Main Camera、Directional Light、Global Volume。
- Inventory、Customer、Trading、加工、日期和睡觉等玩法均未实现。
- 固定视角、2D 场景和可交互 UI 尚未搭建。

## 本阶段边界

不默认加入正式美术、大量商品、复杂顾客 AI、战斗、修炼数值、开放世界或联机功能。存档、UI 技术选型、操作方式及具体经营规则在需要时单独确定，不预建架构。

## 后续需确定

- 营业前配置的最小操作是什么。
- 买入与卖出的触发方式、价格和失败反馈。
- 首批原料、成品与加工规则。
- 营业结束条件、跨日保留和重置的数据。
- 目标分辨率、输入方式与 UI 方案。

这些问题不阻塞本次基础整理，也不授权提前实现相关系统。
