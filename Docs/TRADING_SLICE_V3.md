## 价格规则与迁移

`预估/报价原值 = 基础价值 × (1 + 有效百分比修正之和)`。玩家出售默认 +15%；买入没有额外默认加价，适用的配置标签仍会参与。物品定义的基础价值不会被交易或标签覆盖。

仓库及展示柜的预估值暂用基础价值；谈判柜台采用物品所属交易方向的当前报价。详情显示基础价值、预估值、有效标签、类别和说明；仅实际买入的实例显示购买价值。成交校验、清单单价、总价、实际收支均读取同一套报价计算，标签增删会刷新显示与确认状态。购买价值保存实际支付整数，未来标签或位置变化不重算历史。

临时处理（可替换，不是原版定案）：

- 每件报价按整数四舍五入，中点远离零，然后逐件求和；可售商品最低 1 灵石。极端正报价限制在整数表示范围，出售总额超出可结算范围时拒绝。
- 标签通过稳定 ID 更新；同 ID 替换，不重复叠加，`retail` 保留给默认加价。不同 ID 的修正相加。拒绝缺失 ID、非有限百分比与绝对值大于 100 的标签（即超过 ±10000%）。
- 标签可按类别和交易方向配置；本轮没有市场事件生成、持续天数或声望系统。配置资产的标签在新 Play 会话复制进运行状态，实时修改通过 `SetPriceTag` / `RemovePriceTag`；运行标签持续到移除或 Play 结束。
- 展示吸引权重用基础价值，同类相加，最高类别生效；不使用历史购买价值或谈判报价。开门后权重、方向与预算快照保持不变。
- 旧隐藏 purchasePrice/salePrice 只保留迁移来源，运行交易不读取它们。迁移经 Unity API 原位完成，版本号 1，重复执行不会覆盖已调整的基础价值；旧售价作为新基础值，保留原有展示档位与资产引用。旧购入价只决定原有商品能否由卖家供货。

## 流程和边界

- 五位顾客逐位随机方向，空柜也可营业；默认概率、最高类别、离散资金档位及 ±10% 浮动继续保留。正常随机日不保证同时出现双方；下面的验证日提供确定性入口。
- 买家类别+剩余预算；所有柜台自有商品整体判定，空柜/不可售/类别不符/超预算分别反馈。不部分成交；成功后物品移除、钱与预算同步更新，买家继续停留。
- 卖家物品未付款不可移入玩家仓库。钱或仓库空间不足不扣款，成功收购才更改归属、记录购买价值并移入仓库，卖家自然离场。
- 满柜台现在不会卡死供货队列：卖家可以到访等待；腾出空间后自动摆入，或主动跳过。等待货物不是玩家库存，跳过/闭店不会复制物品。
- 有顾客时按钮为“送别并接待下一位”，无人时为“呼叫下一位顾客”。保留单击主动跳过，没有照搬原版约 1 秒长按。
- 任何阶段自有物品可以在三区域搬运。动态价格不会重算当天客源；形状、旋转、翻转及碰撞回退继续有效。
- 闭店在右侧显示本日交易收入、支出、起始/当前余额及变化。睡觉时保留既有房租逻辑，先支付再建立下一天起始余额；结算页注明房租支付时机。没有新服务开销或完整经济系统。
- 现有丹炉与原料数据保留，仅缩成不抢占交易区域的入口。没有实现仓库型炼丹炉、二级仓库或隔日产出改造。

## 开发者可重复验证（约 5 分钟）

1. 打开 ShopPrototype 并 Play。菜单 **XiuXianShop > Validation > Start Repeatable Trading Day (resets Play session)** 会明确重置当前临时 Play 会话；不修改场景和配置资产，退出 Play 恢复正常开局。
2. 该验证日为种子 0：三颗基础20回气丹，预算60，买卖概率各50%，卖家仅供丹药；仅买入时有测试 -20% 标签，所以收购报价16。把一颗丹药放入展示柜，再开门。此序列为买家、买家、卖家、买家、买家。
3. 仓库选中丹药应显示基础20、预估20且无购买价值。移入柜台后为23，有零售加价+15%；放三颗显示69，预算60时确认禁用。
4. 菜单 **Toggle Sale Discount -30% (Play session)** 加入仅出售生效的测试标签。应立即显示每颗17、合计51，确认解锁。成交后余额171、买家剩余9、三个实例均移除，再点确认不能重复得钱。
5. 送别并跳过第二位买家。第三位卖家报价16，确认收购后余额155；选中货物显示购买价值16、仓库预估20。移至柜台显示当前报价，移回仍预估20，购买价值一直16；可再次切换测试降价菜单验证标签移除后的报价23。
6. 不再成交，依次跳过剩余客人。闭店应显示收入51、支出16、余额变化+35、余额155；睡觉进入第2天，保留这一件买入物品及购买价值16。再次开门可继续测试。
7. 正常拖放验收：旋转木剑/翻转L形、越界或重叠回退、营业后三区域搬运；错误类别照样能放入，确认出售禁用且原因可见。20件长清单可在右侧滚动，固定总价与确认按钮不随列表滚动。

## 文件概要

- ShopPricing.cs：价格标签与不可变报价结果；ShopCatalog：基础值、供货开关、零售加价、标签配置及迁移版本。
- ShopSession：统一报价/购买历史/当日收支；满柜等待和跳过修复，沿用原有库存与客源。
- ShopPrototype：界面骨架、滚动详情、实时标签刷新、结算与清楚的营业状态。
- Editor/PrototypeBuilder：原位迁移、隔离验证日和测试降价菜单；不重建已有场景。
- ShopCatalog.asset：Unity API 保存新增价格配置，原 GUID/场景引用/物品形状与初始库存保留。
- EditMode/ShopPricingTests、现有 EditMode/PlayMode 测试：新规则覆盖与有意义的旧断言更新，新脚本的 .meta 由 Unity 生成。
- Docs：本报告、结构化测试结果、截图，更新设计、计划、日志、试玩与验收入口。

后续建议仅供下一任务：根据正式视觉规格进一步提升小字号及物品识别；取得炼丹二级页规则后再设计仓库型炉子迁移。本轮不实施这些延伸。
