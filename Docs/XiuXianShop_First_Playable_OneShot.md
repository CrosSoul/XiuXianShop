## 一、本次要证明的玩法

这是一个**固定视角、以店铺经营为主体的修仙游戏**。玩家通过收购、出售、加工和经营选择积累灵石，未来再把经营成果转化为修为、装备与其他实力。

本次不做完整游戏，只证明以下闭环：

**整理有限空间 → 配置今日展示 → 开始营业 → 顾客买卖 → 获得/消耗物品与灵石 → 加工提升商品价值 → 结束营业 → 睡觉进入下一天 → 再次经营。**

其中，**空间库存不是附属 UI，而是核心玩法之一**。不要用传统的“物品名称 + 数量列表”代替它。

### 本次交付节点

完成一个可从 Unity Play Mode 进入的原型，让玩家至少能够连续经营两天，并体验到：

1. 有形状的物品在有限格子中拖动、旋转、翻转。
2. 背包、展示柜、谈判柜台之间的物品流转。
3. 展示选择影响当天顾客的交易内容。
4. 顾客买卖导致真实的库存与灵石变化。
5. 一条最小炼丹产业链可以把原料加工成更有价值的商品。
6. 睡觉推进日期，下一天能够继续经营。

**这六项是本次的主目标。**不要为了增加内容数量而牺牲核心交互的可靠性。

## 二、空间物品管理：最高优先级

### 三个主要容器

- **物品栏 / 仓库**：玩家长期储存物品的有限空间。
- **展示柜**：营业前摆放商品或业务招牌，决定当天的经营方向。
- **谈判柜台**：当前顾客与玩家进行交易时使用的临时摆放区域。

三个区域都应体现同一种“格子 + 物品形状”的规则，而不是三个互不相干的库存菜单。

### 玩家必须能够做到

- 用鼠标拖动物品并放入格子。
- 在同一容器内重新整理物品。
- 在允许的容器之间移动物品。
- 手动旋转物品。
- 手动水平或垂直翻转物品；至少提供一种明确可用的翻转操作。
- 看到物品实际占用的格子与放置预览。
- 明确区分合法与非法放置。
- 不能越界、不能与其他物品重叠。
- 非法放置不能导致物品消失、复制或库存状态损坏。
- 旋转、翻转后的实际占格必须正确，而不只是图片转向。
- 旋转、翻转操作应当有可见提示或按钮，不要依赖玩家猜快捷键。

### 最小测试内容

请准备几种明显不同的占格形状，例如：

- 单格物品
- 2×2 物品
- 长条物品
- L 形物品
- 至少一种不规则形状

具体格子尺寸由你根据界面和测试需要决定。暂时不需要物品堆叠、自动整理、仓库升级或复杂容器嵌套。

## 三、店铺与每日营业

### 营业前

玩家可以整理库存，并把商品或业务招牌摆进展示柜。

展示柜的空间有限，因此摆放选择应当有意义。最小版本至少需要让玩家感受到：

> 今天展示丹药，和今天展示收购原料的招牌，会影响今天遇到的交易。

不要求复杂的顾客概率模型，但不能把展示柜做成纯装饰。

### 营业中

至少提供一个完整的顾客交互流程：

**顾客出现 → 提出买入或卖出需求 → 玩家查看交易 → 接受或拒绝 → 物品/灵石结算 → 顾客离开 → 下一位顾客。**

要求：

- 至少有购买玩家商品和向玩家出售商品两种交易方向。
- 顾客物品与玩家物品在谈判柜台上的归属清晰。
- 玩家能够理解交易价格与最终获得/失去的东西。
- 至少支持单件商品的完整交易；多件整单议价、以物换物暂不要求。
- 交易拒绝后不应错误改变库存或灵石。
- 钱不足、物品不足、目标空间不足等情况必须有合理反馈，不能产生负库存、凭空复制或丢失物品。
- 展示柜中的商品如果被卖出，其真实库存状态必须同步更新。
- 不要求复杂谈判小游戏、讨价还价数值或顾客动画。

### 营业结束

玩家可以结束当天营业，进行必要的库存整理与加工，然后睡觉进入下一天。

下一天应当保留合理的持久状态，例如灵石、库存、设备和已推进的日期。当天顾客队列应当正确重置。

## 四、第一条产业链：炼丹

本次只做**炼丹**，不要同时实现炼器、画符、灵田、御兽等其他产业。

目标不是做一个复杂的炼丹小游戏，而是证明：

**收购原料 → 使用设备加工 → 获得成品 → 成品进入空间库存 → 出售成品 → 获得利润 → 有理由继续经营。**

### 最小内容

准备少量可辨认的修仙商品，例如：

- 凝气草
- 灵露
- 回气丹
- 一种额外的低级材料或成品
- 一件形状较大的测试商品

可以使用临时名称与临时数值，不需要正式世界观设定。

至少有：

- 一台丹炉或等价加工设备
- 一条可实际执行的配方
- 一种能稳定获得配方原料的途径
- 一种能出售成品的途径

例如“凝气草 + 灵露 → 回气丹”。具体数量、价格与加工耗时由你自行选择，但请确保：

- 开局资源足够让玩家开始经营，不会被随机数卡死。
- 玩家能够通过正常交易获得原料。
- 加工确实改变物品及其经济价值。
- 成品占用真实格子。
- 空间不足时不能悄悄吞掉原料或产物。
- 至少能够完成两轮“获得原料 → 加工 → 出售”的循环。

设备可以开局拥有，也可以通过一个简单购买入口获得；选择最有利于验证闭环的方案。不要为此制作复杂设备商店或升级树。

## 五、经济与日期：只做必要的压力

需要让玩家理解灵石既是交易货币，也是后续发展的资源。

本次至少保留：

- 当前灵石
- 当前日期
- 商品买卖价格
- 原料与成品的基本利润关系
- 简单的周期性房租或经营支出

房租可以采用每 7 天结算、下一周期上涨约 5% 的简化规则，但本次不需要复杂破产、贷款、通胀或长期经济模拟。

**不要加入固定 72 天倒计时，也不要提前宣布终局危机。**后续剧情会在中期逐渐揭开，目前不需要制作终局。

### 理想完成标准

1. 进入原型主场景。
2. 看见背包、展示柜、谈判柜台和基本经营信息。
3. 拖动一个不规则物品，旋转/翻转后放入原本放不进去的位置。
4. 将商品摆入展示柜。
5. 开始营业，遇到与展示内容相关的顾客。

9. 将成品放入库存并出售。
10. 结束营业、睡觉，进入下一天。
11. 再次营业，确认日期与持久资源正确。
12. 全程没有明显的物品复制、丢失、越界或交易结算错误。
